# 販売情報（価格・在庫）の自動チェック

適合情報（CMS）とは別に、スタンド・壁掛け金具の価格・在庫を販売店ごとに自動で確認して表示する。

> **現状（2026-11-24）**：サンワダイレクトは Cloudflare からのアクセスを HTTP 403 で拒否するため、販売ページは読まない。バリューコマースと提携し、**商品API**（`src/lib/valuecommerce.ts`）から価格・在庫・商品画像・アフィリエイトリンクを取る（`shops.sanwa_direct.source = 'valuecommerce'`）。
>
> - トークンは Cloudflare のシークレット `VC_API_TOKEN`（Workers → tv-fit → 設定 → 変数とシークレット、種類「シークレット」）。Git・README・チャットには書かない。未設定ならサンワダイレクトは確認せず、購入ボタンは販売ページへの直接リンクのまま。
> - 検索はスタンドの型番（`sku`）で行い、結果のうち販売ページURLが一致するもの、なければ同じ販売サイトで型番（`modelCode`/`productCode`）が一致するものを採る。
> - 商品APIに見つからない商品は「一時的なエラー」として記録し、販売終了にはしない（APIに載っていないだけのことがあるため）。
> - アフィリエイトリンク（`link`）は、規約どおり表示数計測タグ（`pvImg` の画像）と必ず対で表示する。どちらかが欠けたらアフィリエイトリンクを使わない。購入ボタンの横に「PR」と表示する（景品表示法のステルスマーケティング規制）。
> - API が返す `http://` のリンク・画像は `https://` にして保存する。
>
> **Yahoo!ショッピング（2026-11-25 追加）**：バリューコマース経由で Yahoo!ショッピングと提携済み。直販サイト（サンワダイレクト）で売っている商品は、Yahoo!ショッピングの**サンワダイレクト公式ストア**（ストアID `sanwadirect`）の出品も確認する（`shops.yahoo_sanwa`、`src/lib/yahoo-shopping.ts`）。
>
> - 価格・在庫・画像は Yahoo!ショッピング商品検索API（v3）。アプリケーションID（Client ID）を Cloudflare のシークレット `YAHOO_APP_ID` に置く。未設定なら確認しない。
> - アフィリエイトリンクは、バリューコマースの Yahoo!ショッピングのプログラムの `sid`・`pid`（シークレット `YAHOO_VC_SID`・`YAHOO_VC_PID`、数字のみ）で商品ページを包んで作り、表示数計測タグと対で出す。未設定なら商品ページへ直接リンク（「PR」なし）。
> - 照合は商品コード `sanwadirect_<型番の小文字>` の完全一致だけ。他のストアの出品は使わない。見つからなければ一時的なエラーとし、ボタンは検索結果へのリンクにする（販売終了にはしない）。
> - 検索結果を表示するので、フッターに「Web Services by Yahoo! JAPAN」のクレジットを出している。
>
> **Amazon・楽天市場**：提携していない。商品ページのURLを持っていないので、「メーカー名＋型番」の検索結果ページへリンクする（`malls`）。アフィリエイトではないので「PR」は付けない。

## 仕組み

- Cloudflare の Cron Trigger（`wrangler.jsonc` の `triggers.crons`、6時間ごと）で `src/worker.ts` の `scheduled()` が動く。
- `scheduled()` は内部経路 `/internal/offer-check`（外部からは 404）を Astro のハンドラーへ直接渡し、`src/pages/internal/offer-check.ts` が公開済みスタンドを読んでチェックする。
- 各スタンドの `product_url`（アフィリエイトリンクなら中の販売ページ）を1秒間隔で取得し、商品ページの schema.org `Product`（JSON-LD）から価格・在庫・画像URL・型番を読む（`src/lib/offers.ts`）。
- 結果は D1 の専用表 `tvfit_stand_offers`（1スタンド × 1販売店で1行）に保存する（`src/lib/offer-store.ts`）。表は初回チェック時に `CREATE TABLE IF NOT EXISTS` で作る。EmDash の表には触れない。

## 判定

| 結果 | 記録 |
|---|---|
| Product データあり | 価格・在庫を更新 |
| 404/410、または Product データなし | `missing_count` を加算。3回続いたら `discontinued`（販売終了） |
| 5xx・通信エラー | 前回の値を維持し `error_count` を加算 |

その回に1件も Product データを読めなかった場合は、販売店側の障害やアクセス制限とみなし、「見つからない」も一時的なエラーとして記録する（全商品が誤って販売終了になるのを防ぐ）。

運用確認用に https://tv-fit.com/offer-status.json で件数・最終確認日時・失敗理由（上位10件）を見られる（価格やURLは出さない）。

## 表示

- 商品カードと比較表に、在庫・価格（税込）・販売店・確認日時を出す。
- 最後に読み取れてから48時間を過ぎた価格は出さない（「在庫は購入先で確認」）。
- 販売終了の商品は購入ボタンを出さず、型番ページ下部の「販売終了品」にまとめる（適合情報は残す）。
- 商品画像は、ASP の商品データが返した画像を商品カードの上部に表示する（CSP の `img-src` は `https:` を許可）。

## 販売店を追加するとき

1. `src/lib/offers.ts` の `shops` に販売店IDと表示名・ホスト名を足す。販売ページを直接読んでよい（拒否されない）販売店だけ `source: 'page'` にする（JSON-LD を持つ直販サイトはこれだけで動く）。バリューコマースの広告主なら `source: 'valuecommerce'`。
2. JSON-LD を持たない販売店（楽天・Yahoo!・Amazon など）は、各社の商品APIから同じ `Offer` 形式を作る取得部品を追加する。
3. アフィリエイトの転送URLは `affiliateRedirectors` に足すと、中の販売ページを確認する。
