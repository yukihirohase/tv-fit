# EmDash 運用ガイド

TV FIT の公開画面を保ち、テレビ・スタンド・適合情報の編集元を EmDash に移す構成です。Astro 7.4.7 と EmDash 1.4.0 を使用します。CMS は Workers 上で動作し、カタログは D1、メディア等は R2 に保存します。

## はじめに管理画面を開く

1. 独自ドメインが有効になった後、[EmDash 管理画面](https://tv-fit.com/_emdash/admin/) を開きます。
2. ChatGPT のログインを求められた場合は、サイト所有者のアカウントでログインします。
3. 初回セットアップではサイト名、本人のメール・名前等を入力し、自分のパスキーを登録します。パスキー登録は本人がブラウザーで行ってください。
4. テレビ・スタンド・適合情報の3つのコレクションが表示されることを確認します。サンプル製品を投入する必要はありません。

最初の管理者作成は運営者本人が行い、登録直後に通常のログインを確認します。パスキーはホスト名に結び付きます。`tv-fit.com` の取得・DNS 設定・TLS 有効化が完了してから登録してください。

## データを編集する順序

1. **テレビ**：`external_id`、メーカー、正式型番、確認できた仕様、公式仕様 URL を入力して下書きを保存します。
2. **スタンド**：`external_id`、メーカー、商品型番、タイプ、耐荷重、確認済み VESA パターン、公式 URL、購入 URL を入力します。
3. テレビとスタンドの出典・内容を確認し、それぞれを **公開** します。
4. **適合情報**：対象テレビとスタンドの `external_id` を `television_id` / `stand_id` へ入力し、適合区分、根拠種別、出典、確認日、注意事項を入力します。
5. 個別の根拠を確認したうえで適合情報を公開します。メーカー別一覧・型番詳細を再読み込みし、表示を確認します。

保存しただけの下書きは、公開画面には反映しません。公開済みデータも、形式とカタログの整合性を検証してから表示します。一般的な DB・権限・通信エラーを「型番未登録」と読み替える処理は行いません。

### 2種類の「状態」

- EmDash の状態：下書き／公開。サイトへ掲載するかどうかの編集状態。
- `compatibility_status`：`confirmed` / `candidate` / `incompatible` / `unknown`。製品の取り付け適合に関する区分。

「公開」を選んでも、適合確認済みに変わることはありません。VESA と重量の一致だけで `confirmed` に自動昇格する処理はありません。個別適合確認済みには、メーカー等による個別の根拠 URL と確認日・注記が必要です。

### 項目の注意点

- EmDash は `id` と `status` を内部で使用するため、CSV の `id` は `external_id`、CSV の適合 `status` は `compatibility_status` に対応させています。
- 外部 ID は同じ製品を識別する固定値です。正式型番の表示文字列とは分けて管理します。
- 参照先 ID は、CMS 内部のランダムな ID や URL 用 slug ではなく、テレビ・スタンドに入力した `external_id` です。
- 重量は取り付け対象となるテレビ本体の値かどうかを確認します。スタンド込みの重量と混同しないでください。
- VESA は `200x200;400x400` の形式で、確認できたパターンだけを列挙します。
- `checked_at` は `YYYY-MM-DD` の暦日です。存在しない日付・未来日を入力できません。
- 空欄のテレビ仕様は「未確認」として扱います。推測値を入力しないでください。
- ネジ径・長さ、スペーサー、背面の段差や端子干渉、床や壁の条件は根拠に合わせて `notes` に記録します。

## CSV を取り込む

CSV は交換・取込用です。取込後の編集元は CMS に統一します。CMS の内容が自動で `data/*.csv` に書き戻されることはありません。

### まず検証だけ行う

```sh
npm run cms:import
npm run cms:import -- --directory data
```

この状態では API 通信も書き込みも行いません。CSV の列、数値、URL、日付、ID、参照、型番の正規化衝突、適合根拠を検証し、取込候補件数を表示します。架空と明示した fixture は本番の取込対象にできません。

### API 認証を準備する

EmDash の管理画面で、対象 CMS に対してコンテンツの読取・書込ができる API トークンを作成します。トークンのスコープは `content:read`・`content:write`、ユーザー権限は既存下書きを確認できるものを使用します。トークンをチャットに貼ったり、リポジトリへ保存したりしないでください。

次の2つの環境変数を、実行するターミナルのセッションに設定します。

| 環境変数 | 内容 |
| --- | --- |
| `EMDASH_BASE_URL` | API を利用できる CMS のオリジン。例：`https://自分のCMSドメイン` |
| `EMDASH_API_TOKEN` | 管理画面で発行した非公開 API トークン |

HTTPS のオリジンだけを受け付けます。ローカル開発に限り `http://localhost:4321` 等のループバック HTTP を使えます。パス・クエリ・認証情報を URL に含めないでください。

本人限定 Sites の外側の ChatGPT ログインは、EmDash の Bearer トークンでは通過できません。この CLI は直接 Cloudflare に配信した CMS、または信頼できるローカル開発環境の API を利用してください。Sites の本人限定版ではブラウザーの管理画面から編集できます。CLI はログインページへのリダイレクトをたどらず、接続先を確認できない場合は中止します。

### 下書きとして取込を実行する

```sh
npm run cms:import -- --directory data --apply
```

処理は次の順序です。

1. 3つの CSV 全体を検証する。
2. 対象 CMS のテレビ・スタンド・適合情報を、下書きも含めて全ページ取得する。
3. 同じ外部 ID・適合ペアについて、同じ内容ならスキップする。違う内容が存在したら、書き込み前に中止する。
4. テレビ → スタンド → 適合情報の順に、すべて **下書き** として作成する。

取込は既存の内容を上書きせず、公開操作も行いません。取り込んだ下書きは、上の編集手順に従って出典と条件を確認してから公開してください。複数 API リクエストによる取込なので、通信が途中で失敗した場合、先に保存された下書きが残ることがあります。管理画面で確認してから再実行してください。同じ内容の行は再実行時にスキップします。

## 公開済みデータを CSV に書き出す

API 認証を設定した状態で、まだ存在しない出力ディレクトリを指定します。

```sh
npm run cms:export -- --out work/cms-export
```

公開済みのテレビ・スタンド・適合情報を取得・検証し、元の3つの CSV 列構成へ書き出します。CMS の内部 ID や下書き状態を、CSV の製品 ID・適合区分として書き出すことはありません。既存ディレクトリへの出力は拒否し、以前の CSV を上書きしません。

この書出しはカタログ交換用です。管理者・パスキー・下書き・履歴・CMS設定等を含む完全バックアップではありません。

## 開発環境の準備

Node.js 24 と npm を用意し、このプロジェクトのフォルダーで実行します。

```sh
npm ci
cp .env.example .env
npx emdash secrets generate --write .env
npm run dev
```

暗号化キーは `.env` 等の gitignore 対象ファイルへ生成します。Workers 向けのローカル実行では、Wrangler のローカルシークレット設定と実行環境に同じ `EMDASH_ENCRYPTION_KEY` を渡してください。設定ファイル名と起動コマンドは、このプロジェクトの最終的な開発設定に合わせます。

`EMDASH_ENCRYPTION_KEY` は暗号化した設定の復号に必要です。実運用のキーを変更・紛失すると、保存したプラグイン等のシークレットを復号できなくなります。Git に含めず、CMS のデータベースと合わせて安全な場所にバックアップしてください。

ホームディレクトリが読み取り専用の場合、`npm_config_cache`、`XDG_CONFIG_HOME`、`XDG_CACHE_HOME`、Wrangler のログ先を `/workspace/work/` 等の作業ディレクトリに向けます。`ASTRO_TELEMETRY_DISABLED=1` は Astro テレメトリーを無効にします。

## 自分の Cloudflare アカウントへ直接配信する

EmDash はデータベースと管理画面を実行するため、静的サイト用 Cloudflare Pages 設定では動作しません。Workers と、永続 D1・R2 を用意します。

1. Cloudflare のアカウントにログインできる状態にします。
2. プロジェクトの `wrangler.jsonc` の Worker 名、D1 のデータベース名、R2 のバケット名を、自分の運用名に合わせます。コードの `DB`・`MEDIA` 等のバインディング名は設定と一致させます。
3. `npx wrangler login` を実行し、ブラウザーで自分のアカウントを認証します。認証情報をチャットへ貼り付けないでください。
4. `npx wrangler secret put EMDASH_ENCRYPTION_KEY` で、保管した実運用のキーを設定します。
5. `PUBLIC_SITE_URL` に公開先の HTTPS オリジンを設定し、`PUBLIC_INDEXING_ENABLED=false` のままビルドします。
6. `npm run build` の後、`npx wrangler deploy` で配信します。Wrangler は設定された名前の D1・R2 を利用・作成します。既存のデータベース名を不用意に変更しないでください。
7. 実際のホスト名で管理者作成とパスキー登録を完了し、管理画面、メーカー一覧、公開データの更新、購入先、canonical、noindex を確認します。
8. 実在データ・広告契約・運営方針が整った段階で、意図した本番環境だけインデックスを許可します。

初期の3コレクションは予約公開を有効にしていません。即時の「公開」操作を使用します。将来、予約公開や EmDash の定期処理を使う場合は、公式ガイドに従って Cron Trigger と Worker の `scheduled` ハンドラーを両方設定してください。

## バックアップと更新

- D1 のデータ、R2 のメディア、暗号化キーをそれぞれ保管します。カタログ CSV だけでは管理アカウントや編集履歴は復元できません。
- 更新前に DB のバックアップを確認し、EmDash の公式マイグレーション手順を読みます。
- 適用済みのマイグレーションを改変せず、バージョンアップ時の復旧手順を用意します。
- インストールする追加プラグインの権限を確認します。TV FIT の適合検証機能を外した状態で運用しないでください。

## 検証状況

CSV 取込・書出し処理の単体テストは、API 通信をモックして確認します。実運用の API トークン、実在製品、管理者パスキーを自動生成して試験することはありません。最終の型チェック・全体テスト・ビルド・配信・ブラウザー検証状況は、親の移行作業完了時に追記します。
